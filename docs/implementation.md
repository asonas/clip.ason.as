# 実装の進め方

設計の原本は[承認済み計画](product-plan.md)。ここでは最初の実装で完成させる範囲を定義する。

## Problem Statement

Web上の文章と画像を、自分のコメントと出典とともに蓄積したい。自分のサイトで読め、AT Protocolでも扱える形にする。

## Solution

自分専用のChrome拡張から投稿し、PDSの公開レコードを原本としてclip.ason.asに表示する。下書き機能は作らない。Cloudflare Paidの既存契約を使い、PDSはCirrusを先に検証する。

## User Stories

1. 投稿者として、選択した文章を引用欄へ取り込みたい。
2. 投稿者として、選択した画像と出典ページを取り込みたい。
3. 投稿者として、自分のコメントと引用文を分けたい。
4. 投稿者として、投稿前に内容を確認したい。
5. 投稿者として、投稿した内容を後から更新・削除したい。
6. 投稿者として、通信障害時に同じ投稿を重複して作りたくない。
7. 投稿者として、必要なクリップをBlueskyにも紹介したい。
8. 閲覧者として、JavaScriptなしで公開した文章と画像を読みたい。
9. 閲覧者として、出典へ移動したい。
10. 閲覧者として、クリップの固定URLを共有したい。
11. 運用者として、閲覧のたびにPDSへアクセスしたくない。
12. 運用者として、PDSのデータと画像を復元できるようにしたい。

## Implementation Decisions

- TypeScriptとCloudflare Workersを使う。
- 最初は取得済みのAT Protocolレコードから静的HTMLを生成する。PDSの取得と閲覧を分離する。
- 公開本文はプレーンテキスト。引用とコメントを別々に表示し、HTMLとして実行しない。
- 画像は配信用コピーのマッピングを受け取る。公開HTMLからPDSの原寸画像を直接参照しない。
- Chrome拡張の初期実装はコンテキストメニューから取り込み、拡張内のフォームで確認するところまで。公開前の入力をサーバーへ送信しない。
- OAuth、実際の画像アップロード、PDSへの書き込み、D1/R2の本番リソースは後続作業。
- Lexicon名は暫定の`as.ason.clip.entry`。本番データ作成前に確定する。

## Testing Decisions

- 公開レコードと配信画像マッピングを入力し、生成されるHTMLを検証する。引用とコメント、出典、安全なリンク、固定URLを確認する。
- 拡張のコンテキストメニュー入力から確認画面の入力値までを検証する。Chrome APIだけを外部境界として置き換え、内部関数をモックしない。
- PDSの実接続、ブラウザ権限、実際の拡張ロードは別に確認する。ユニットテストの成功だけで認証・配信が完成したとは扱わない。

## Out of Scope for the initial implementation

最初のコード作成は公開HTML生成と拡張への取り込みまで。OAuthと公開処理、実画像取得、Cirrusの本番配備、アカウント作成、Figmaによる最終デザインは含めない。

## Further Notes

作業はLinearのAsonasチーム（キーASO）で管理する。依存はHTML生成・拡張取り込み・PDS検証の3本が公開処理に合流し、更新・削除・Bluesky配信がその後に続く。
